# Design and scope

The launcher owns orchestration; Apple's installed Xcode tools own compilation,
provisioning and device communication. There is no alternative signing service.

| Responsibility | Implementation |
| --- | --- |
| CLI and orchestration | `ios_one/cli.py` |
| Team fallback | `ios_one/signing.py`, public certificate subjects matched to valid development identities |
| Source distribution | `ios_one/distribution.py` and `scripts/package_release.py` |
| Example project | Checked-in Xcode project generated by `scripts/generate_example.py` |
| Initial publication | `scripts/publish.py`, explicit source allowlist and new Git repository |

Selection uses exact identifiers, saved preferences and explicit choices. Each
project's absolute container path gets a separate state directory. Runs for the
same project are serialized. Settings are atomically replaced. A scheme/configuration
change does not reuse a different scheme's saved signing/target profile.

Build commands use argument arrays with no shell evaluation. Output is captured
in private files, with a heartbeat and time limit. Interrupts terminate the spawned
process group. Installation starts only after a successful build and a matching
built bundle ID/package type/executable check. The selected app product must lie
inside the assigned DerivedData directory.

Signed identities are parsed from `security find-identity -v -p codesigning`.
The certificate's DER fingerprint is matched to that identity; its OU supplies
the Team ID. The SHA-1 fingerprint is only a lookup handle, not a trust/signature
decision. No private key export or keychain mutation is performed by this code.

## Provenance

The design and certificate-reading routine were adapted from masaaki office's
existing app-specific development launchers. The public distribution contains a
new generic CLI and a dedicated HelloDevice sample. It does not include the
private app code, user settings, app assets, signing identities or customer data
from those projects. The generic orchestration is new and requires its own Mac
and real-device verification.
